## When to Use
Use when filling a voluntary health insurance claim form - a multi-page AcroForm with contractor, insured, event and declaration blocks - or the equivalent step for any AcroForm PDF that must be filled from Paperless records. Also applies to the general task of filling a blank government or insurer PDF from data archived in Paperless on NixOS. The blank form is stored in Paperless as a `Template` document; person data lives in `Person` custom fields and company data in `Company` custom fields. Requires Paperless reachable (see the project notes for the port-forward and API token secret) and Nix available for ephemeral tooling.

Two facts this procedure depends on, worth checking before the first fill: the form has no date-of-birth field, so that value belongs only in the covering email; and the patient-specific versus event-specific split of the fields is fixed - patient identity comes from the Person record, while event date, institution, cause, diagnosis and amount come from the receipt and the matching medical report, never from the receipt alone since receipts carry no diagnosis.

See also the companion skill `insurance-claim-package-and-send`, which covers grouping several receipts into insured events, assembling one folder per claim, converting photo scans into submittable PDFs, and generating the covering email drafts. Use this skill for the form itself and that one for everything around it.
## Procedure
1. Identify the claim: which subject it is for, and which event it covers (a visit, treatment, purchase or stay). Ask if the request does not name both.
2. Gather the subject's data from their Person record. Person records live in a dedicated document type; every identity, contact, employment, policy and bank detail belongs there as a typed custom field. Read the record and its custom fields with `paperless_list_documents({ document_type: <person type id>, page_size: 50 })` — each result carries a populated `custom_fields` array. Treat these typed values as authoritative and never re-derive them from scanned text. If a needed field is empty, ask the user instead of guessing.
3. Collect the evidence for the event. Search for the subject's documents with `paperless_search_documents` using `type:receipts AND tag:<subject tag>` and the report/lab document types, bounded by the claim period. Read each one with `paperless_get_document_content`. From receipts take the provider, the date of service, the itemised services and the total amount paid; from medical reports take the diagnosis, the cause of the event and any prescribed treatment. Match the reports against the receipts so the claim narrative and the amounts agree.
4. Work out who the policy holder (contractor) is before writing anything. Read the form's own wording: a corporate or group policy is contracted by an employer while the treated person is the employee. Only the person who holds the policy belongs in the contractor block; the payout account may still be the patient's own. Ask the user when the form does not make it obvious.
5. Fetch the blank form's ORIGINAL file, not the archived copy, because PDF/A ingestion may drop AcroForm fields. Download it through the Paperless REST API with the `original=true` query parameter, writing the response straight to a file so the bytes never pass through the model context. The MCP download tool returns the same file as base64, which floods the context for anything but a trivial PDF.
6. Enumerate the form's fields and their geometry: `nix run nixpkgs#qpdf -- --json --json-key=acroform form.pdf` for names and types, then `nix run nixpkgs#qpdf -- --qdf --object-streams=disable form.pdf dump.qdf` and parse `/Subtype /Widget` dictionaries for `/T (Name)` and `/Rect [x0 y0 x1 y1]`. PDF y grows upward, so sort by `-y1` to get top-to-bottom reading order.
7. Map every field to its visible label by geometry. Render the page — `nix shell nixpkgs#poppler-utils -c pdftoppm -png -r 130 form.pdf page` — and look at it, cropping with `-x -y -W -H` to inspect a single block closely. Compute the px-to-pt scale from the dpi (`dpi / 72`) and convert with `y_px = (page_height_pt - y_pt) * scale`. When a label's meaning is ambiguous, resolve it with exact word coordinates from `pdftotext -bbox` before filling, and confirm your reading of any unusual line with the user.
8. Build a JSON mapping of field name to value, drawing each value from the Person record or the evidence, then fill from the pristine template using pypdf. Locate the library with `PYP=$(nix build --no-link --print-out-paths nixpkgs#python3Packages.pypdf)`, find its `site-packages` directory, set `PYTHONPATH` to it and run the system `python3` with a script that does `PdfWriter.append(PdfReader(src))`, `writer.set_need_appearances_writer(True)` and `writer.update_page_form_field_values(page, values)` for each page. Pass only non-empty values so blanks stay blank.
9. Verify the result before showing it. Read the written values back with `nix run nixpkgs#qpdf -- --json --json-key=acroform filled.pdf` (a `u:` prefix on the printed value is normal unicode string encoding, not corruption) and compare every identifier digit for digit against its Paperless source. Then render the filled page and inspect placement, clipping and glyphs. Report how many fields were populated out of the total so silent omissions are visible.
10. Stamp the signature, if the form needs one. Keep one signature document per person in Paperless under a dedicated document type, tagged with that person's tag so it is found by `type:signature AND tag:<person>`. Download it through the REST API straight into a file rather than through MCP, so the image never enters the model context. Ensure the asset is a tightly cropped PNG with a transparent background; if it is a one-page PDF, use it as-is. When the asset is a raster image, wrap it into a PDF first with `nix run nixpkgs#img2pdf -- sig.png -o sig.pdf` and confirm the log reports a soft mask, because a flattening converter produces an opaque white box that hides the printed rule. If the source is a photograph rather than a clean scan, flat-field it first (see Pitfalls) so uneven lighting does not leave a grey veil over the form.
11. Place the stamp from the form's own signature field rectangle, scaling by HEIGHT so it fits the band. Derive placement from the `/Rect` of the signature field and check what sits above it, since an under-label there limits the usable height. With pypdf: `writer.pages[0].merge_transformed_page(sig_page, Transformation().scale(h / sig_page.mediabox.height).translate(x, y))`. Stamp only after the user has reviewed and approved the filled form.
12. Re-verify after stamping — re-run the field read-back and confirm the AcroForm still has the same field count and values, then render the signature strip and inspect that the signature sits on the rule, the rule is still visible and nothing above it is covered. Report the exact placement and size.
13. Present the finished form for approval, noting any field that had to be guessed, left blank or written in a shortened form, and stating whether a signature was stamped. Only after explicit approval, upload it with `paperless_post_document` and `poll: true`, and tag the source receipts with the reimbursement tracking tag via `paperless_edit_documents_bulk({ documents: [...], method: 'add_tag', tag: <tag id> })`. Leave any reference number the receiving organisation assigns empty.
## Pitfalls
- Never transcribe identifiers, dates of birth or account numbers from OCR text of scanned documents — OCR misreads digits, which is fatal on a claim. Read them from the typed custom fields of the subject's Person record and have the user confirm the digits before filing.
- A stored signature is an authorization credential, not just an image: anything that can read that document can sign as that person. Never fetch it through MCP tooling, because document content is forwarded to the LLM provider and the image bytes would enter the model context. Download it over the REST API straight into a file, and never commit it to a repository.
- Never sign automatically. Stamp only after the user has reviewed and explicitly approved the filled form, since the signature is what makes the document binding.
- A signature asset must be tightly cropped with a TRANSPARENT background. A crop with a white background behaves as an opaque rectangle and will cover the printed signature rule and anything beneath it. If the source is a photo or scan on paper, remove the background to alpha before use.
- Wrapping a transparent PNG into a PDF preserves transparency only when the converter emits a soft mask: verify with `img2pdf` (it logs `Computing a separate soft mask (/SMask) image`), then confirm the resulting PDF actually contains an `/SMask`. Tools that flatten to white silently ruin the overlay.
- Keying white alone fails on photographs of paper: uneven lighting leaves a partially opaque grey veil and the trim box stays page-sized (measured: bbox 1200x295 instead of the 957x248 ink extent, with only 78% of pixels transparent). Flat-field first — `magick in.png -colorspace Gray \( +clone -blur 0x40 \) -compose Divide -composite -level 0%,60% -negate -alpha copy -fill black -colorize 100 -trim +repage sig.png` — which normalises illumination, yields the exact ink bounding box and leaves the paper fully transparent (max alpha 0 outside the strokes). Do NOT use `-normalize` on a photographed signature: it stretches the lighting gradient into the strokes and destroys the mask (measured: only 2.9% transparent pixels).
- Size the stamp to the form's own signature band, not to taste. Derive the band from the signature field's `/Rect` and check what sits above it — under-labels are often positioned directly above the signature area and a taller stamp collides with them. Scaling to the full band width usually makes the stamp impossibly tall; scale by height instead.
- Stamping can disturb the AcroForm. Re-run the field read-back after stamping and confirm the field count and values are unchanged.
- `paperless_update_document.custom_fields` REPLACES the entire custom-field array — it does NOT merge. Sending a single field silently deletes all the others, so always send the COMPLETE field set, or use `paperless_edit_documents_bulk` with `method: 'modify_custom_fields'`. Same trap as the `tags` array. Re-read the document afterwards and compare the field count.
- Read the form's own labels before assuming who the contractor is. A claim is often filed under an employer's group policy while the treatment belongs to an employee; the contractor block then carries the company, not the patient. Ask when the form does not make it obvious.
- Words can be inline between two blanks or printed as under-labels beneath them, and the two mean different things. Decide with coordinates from `pdftotext -bbox` rather than by eye. One blank may be intended to hold a whole date rather than a single number.
- Never fill the signature line with typed text and never fill a reference number the receiving organisation assigns (claim number, protocol number). Leave them for the human or for the actual signature stamp.
- The archived PDF/A copy may not preserve AcroForm fields — always download the template with the `original=true` query parameter, and never run OCR `redo`/`force` on it, which rasterises the form.
- Paperless advanced query syntax works only through `paperless_search_documents.query`; `list_documents.search` is plain full-text. Negation is `NOT tag:x` — a leading dash does NOT negate.
- Paperless upload endpoint is `/api/documents/post_document/` and its multipart FILE field is named `document`, not `file`. Posting `file=@x.pdf` returns `No file was submitted.`
- `custom_fields` on that upload endpoint must be a JSON object mapping field IDs to values. A JSON list of field/value objects is rejected with `Custom fields must be a list of integers or an object mapping ids to values.`
- The upload endpoint is asynchronous — it returns a task UUID, so sleep briefly and then query the documents endpoint filtered by the document type to confirm that the document and its custom fields actually landed.
- To replace an existing document's file while keeping the same document ID, use the version endpoint (`/api/documents/<id>/update_version/`, multipart field `document`) rather than deleting and re-uploading.
- A failed MCP write can surface as `The socket connection was closed unexpectedly` — the write may or may not have landed. Re-read the document, then retry; retrying via `edit_documents_bulk` with `method: 'modify_custom_fields'` worked.
- `nixpkgs#poppler_utils` was renamed — use `nixpkgs#poppler-utils`. `pdftotext -bbox` reports y growing DOWN the page, the inverse of the PDF field coordinates that qpdf reports.
- `nix shell nixpkgs#python3Packages.pypdf -c python3` fails: the shell's python does not get pypdf on its path. Use `PYP=$(nix build --no-link --print-out-paths nixpkgs#python3Packages.pypdf)`, set `PYTHONPATH` to the `site-packages` directory under that store path, and run the system `python3` (its minor version must match the packaged build).
- `nix shell` with parenthesised flake attributes such as `python3.withPackages(...)` fails with `getting status of .../nixpkgs`. Avoid parenthesised attributes; use `nix build --print-out-paths` instead.
- Generating a small info PDF needs no Python PDF library: author a PostScript file and run `nix shell nixpkgs#ghostscript -c ps2pdf in.ps out.pdf`, then verify the text with `pdftotext`.
- Harmless noise: `eval-cache-v6 ... sqlite is busy` from concurrent nix evaluation. Ignore it, or set `NIX_CONFIG='eval-cache = false'`.
- Use ASCII transliteration for diacritics in field values: Helvetica/WinAnsi forms may not render letters with carons or acute accents, so transliterate rather than risk a missing glyph.
- Long values can render clipped when the box is narrow, for example an e-mail address. The stored value is complete; check the render before assuming data loss.
- Fill from the pristine template every time, never from a previously filled copy, so a bad value cannot silently persist.
## Verification
1. `qpdf --json --json-key=acroform filled.pdf` shows the intended value on every field you set, and `None` only on fields deliberately left blank.
2. Every identifier and amount was read back from the PDF and compared digit for digit against the Paperless Person record or the source receipt.
3. No value originates from OCR text of a scan.
4. The rendered PNG of the filled page shows each value inside its intended box, with no clipped critical numbers and no missing glyphs.
5. The output was produced from the untouched template, never from a previously filled copy.
6. The user reviewed the form and approved the content before any upload.
