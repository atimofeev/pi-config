## When to Use
Before promoting Terraform, Terraformer, cf-terraforming or embedded-provider upgrades in backup images, especially when exports succeed but generated configuration fails or resources disappear. This procedure permits approved read-only exports and local validation, not apply, destroy or remote-state mutation.

## Procedure
1. Pin the published baseline by immutable registry manifest digest and the candidate by its exact local image ID. Record CLI/provider versions, source-input hashes and scan DB timestamps. Never convert a local image configuration ID into repository@digest; inspect it locally before cloud work.
2. Use separate private temporary roots (directories 0700, owned reports/logs 0600), with no repository output mounts. Obtain approved read-only credentials in RAM and pass Docker environment-variable names, never values. Do not trigger pipeline commit stages.
3. Replay the current backup script and exact CI service/region commands for a representative account. Exclude retired endpoints consistently. Compare command exits and sanitized logs, including partial failures and skipped resources; exporter exit zero is insufficient.
4. Compare state v3 primary/v4 instance identities, declarations and attributes by scope/type/ID. Canonicalize policy JSON. Normalize array order only where domain semantics justify it, preserving duplicates and meaningful values. Track parse failures and skipped files explicitly.
5. For cf-terraforming generate, compare parsed full-body multisets scoped by parent/type, omitting generated labels only. Distinguish additions/removals from renaming. Do not claim API-ordering causality without evidence.
6. Use each image's own provider schema for structural checks, then run native terraform validate -json on every resource-bearing module. JSON schemas omit SDK ranges, conflicts and dependent-argument rules. Use network-disabled containers, matching cached provider/lock files, a read-only fixture and explicit workdir; no credentials, init, plan or refresh.
7. For candidate failures, run paired baseline controls and compare full error summary/detail multisets. Normalize only source positions and numeric schema indexes, not field names, ranges, dependencies or actual values. Retain raw diagnostics privately; emit only allowlisted metadata/hashes. Separate diagnostic occurrences from module counts.
8. Prove suspected exporter normalization with minimal good/bad provider fixtures and native Go table tests. Fix exporter constructors/hooks, not official provider binaries or captured outputs. Remove only proven unset/redundant values; preserve positive, configured, unknown and nondefault cases and unchanged state attributes. Check actual conversion/filter/hook order and item shape.
9. Expand approved account coverage with bounded concurrency and stop assigning new accounts on new completeness, native/structural validation, parse, log or privacy failures. Let active read-only workers finish. Explicitly list skipped accounts; partial local validation is not full-matrix acceptance.
10. Reuse baseline captures only explicitly after verifying exact successful commands, positive output evidence, identities, declarations, file inventories and byte hashes. Skip scaffolding symlinks. Explain that hashes computed after capture attest a checkpoint, not original capture-time provenance.
11. For nonempty user data, inspect metadata only and compare raw/base64 paths without printing content. Base64 is not confidentiality. Passing observations do not prove every fallback path is safe.
12. Scan the final immutable image including hidden downloaded providers; verify actual critical count and report image ID, not exit code alone. Keep security, export completeness, semantic fidelity and native configuration acceptance separate. Report pre-existing defects and untested restore behavior.

## Pitfalls
- Container-created links into image paths can dangle on the host. Skip links before reading, count omissions, and never recursively chmod/chown container-owned output or follow links.
- Use one coherent Python withPackages environment for HCL tooling; clear inherited Python path/home variables when native-extension ABIs are mixed.
- Structural schema success and matching resource counts can conceal invalid configuration and changed writable fields. Native validation is mandatory, but even native success does not prove apply/replacement semantics.
- A failing baseline can have different defects from the candidate. Compare full constraints rather than declaring every candidate failure pre-existing. A relaxed numeric upper bound on an already-invalid zero is not newly invalid configuration.
- Numeric zero is not globally disposable. Omit it only for the specific resource/field when raw state and provider controls prove it represents an unset invalid default. Configured alarm criteria and positive/unknown values must remain.
- An optional logging block can be disabled yet require a bucket when exported. Omit only explicitly disabled, unconfigured blocks; preserve configured bucket/prefix and enabled cases.
- New optional/computed primary-interface metadata can conflict with historical inline networking. A conservative projection requires known matching IDs and default lifecycle metadata, no explicit legacy interface, valid inline fields and the exact converted shape. API-observed defaults do not establish original NIC ownership or identical replacement behavior.
- AWS provider major changes can stop backfilling required S3 bucket-policy identity. Seed the bucket in the exporter resource constructor rather than editing output or official providers.
- A null resource-read response does not by itself prove genuine deletion. Inspect wrapper diagnostic handling and provider not-found behavior; correlate captured evidence before attributing API drift or provider regression. Initial read failures and follow-on refresh failures are not independent API failures.
- Synthetic causal fixtures must validate without the suspect field/block; eliminate unrelated required/configuration errors first.
- When only an unrelated exporter binary changes, earlier Cloudflare evidence may be reused if generator, Terraform, provider, script and lock hashes, runtime configuration and dependency layers match. State explicitly that evidence is reused, not a new API replay of the final image.
- Do not dump full reports or source snippets from private exported configuration: resource IDs, policies, user data and secrets can leak through diagnostics. Filter before console output, including delegated work.
- Never automatically retry stopped cloud runs, silently broaden scope or bypass checksums/CVEs. Timeout cleanup targets only harness-owned containers, never Docker prune.

## Verification
1. Retain private inputs/results with exact images, commands, exits, provider versions, account/module coverage, empty/skipped scopes, native controls, semantic deltas and privacy counters.
2. Verify actual files, image IDs, scan JSON and full diagnostic differences rather than trusting completion summaries. Explicitly distinguish previously validated runtime components from new-image replays.
3. Report blockers, pre-existing invalid modules, skipped accounts and limits on semantic/privacy/restore claims. Confirm no production writes, apply/destroy/refresh, remote-state updates, pipeline commits or pushes occurred.
4. Compute total validation executions as candidate records plus actual baseline controls. A coarse parser's unclassified diagnostic list is not a setup failure when JSON parsed and no timeout occurred. Independently compare raw severity/address/summary/detail tuples; SDK range messages may live in summary rather than detail.
5. For newly representable configurations, compare positive state block counts with exact same-scope HCL AST bodies. Empty blocks such as ASN aggregation can carry meaning despite having no attributes, and native validation may miss their omission. Check both baseline and candidate before calling an omission a new regression.
6. Read captured V3 attributes as flat maps rather than assuming nested API/list shapes. Reconcile guards using raw count keys and leaf counts before loading credentials; a diagnostic parser bug must not broaden the approved resource set. Ordinary reads of readable container-owned files do not require ownership changes.
7. Allowlist console primitives and suppress user-defined tag/map keys as well as values and IDs. Inspect permissions of automatic tool spill files containing private output; restrict only owned regular files without following links, never recursively modify captured output.
8. Recheck recorded scanner DB UpdatedAt/NextUpdate against promotion time. A historical zero-critical scan is evidence for that DB snapshot, not proof that a later promotion uses current vulnerability intelligence. Do not silently refresh or bypass a stale acceptance gate.
9. Persist each completed Docker command's exit receipt before parsing, permissions checks or cleanup. Recover missing receipts from exact harness-owned Docker die events when available; stdout alone is not proof of exit zero. Resume only unexecuted commands after an authorized local correction.
10. Preflight export containers as host UID:GID with writable ephemeral HOME and umask077 before loading credentials. Verify private directories0700 and reports/helpers/logs0600. Terraformer-generated TF/state files may be0700: owner-execute does not expose data, so accept0600/0700 with no group/other access. Skip image-relative scaffolding symlinks before every HCL or lexical privacy read.
11. An approved existing S3 read gap must match operation GetBucketLocation, code AccessDenied, HTTP403 and bounded per-command counts. AWS enhanced denial descriptions can include actor/resource ARNs and an explicit resource-policy deny; do not require the literal short message Access Denied or print enhanced details. Test actual private logs in RAM plus mixed-error rejection controls before cloud continuation; other errors remain blocking.
12. Distinguish local named-profile SSO TokenRetrievalError from exporter failures. Verify whether any new export actually started. Request normal user SSO login rather than switching identities, falling back to another credential store, changing permissions or automatically retrying. Preserve captures and completed receipts across the pause.
